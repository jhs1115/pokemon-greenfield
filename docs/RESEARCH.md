# 수집 자료 및 설계 기준

## 수집한 것

PokéAPI 공개 CSV 스냅샷을 `data/raw`에 저장했습니다. 수집 날짜와 출처는 `data/reference.json`에 기록합니다. 원본 데이터는 세대별 변경을 모두 정규화한 단일 규칙집이 아니므로, 실제 게임 규칙은 대상 세대를 정한 뒤 추가 검증해야 합니다.

| 자료 | 범위 |
| --- | --- |
| 포켓몬 | 대체 폼 포함 1,351개 항목, 키·키/몸무게·한국어 이름 |
| 능력치 | HP / 공격 / 방어 / 특수공격 / 특수방어 / 스피드 종족값 |

| 기술 | 937개 항목의 타입·위력·PP·명중률·우선도·피해 분류·대상·효과 ID |

현재 정규화 데이터는 특성 설명이나 기술의 모든 효과를 실행 가능한 코드로 변환하지 않았습니다. 특성/진화 원본은 참고용이며 현재 게임에서는 발동하지 않습니다. 도감의 한국어 이름은 원본 한국어 언어 ID 3을 사용합니다.

## 원작 데이터에서 사용하는 기준

1. 기술 우선도가 스피드보다 우선합니다. 같은 우선도면 스피드, 동률이면 무작위입니다.
2. 물리 기술은 공격/방어, 특수 기술은 특수공격/특수방어를 사용합니다.
3. 복합 타입 상성은 곱셈으로 계산합니다. 0배 무효는 최소 피해 규칙보다 우선합니다.
4. 자속 보너스는 1.5배로 적용합니다. 특수한 특성, 테라스탈 등은 제외합니다.
5. 레벨 20, 개체값 31, 노력치 0, 성격 보정 1배 기준으로 전투 능력치를 계산합니다.
6. 피해는 `floor((floor((2L/5+2) × 위력 × 공격 / 방어 / 50)+2) × 자속 × 상성)`을 사용하는 초안용 단순화입니다. 원작의 단계별 반올림과 모든 보정을 재현하지 않습니다.

## 이 게임에서 새로 정한 규칙

- 10×7 전장, 1칸에 1마리, 턴당 인접한 8방향 중 한 칸 이동 또는 제자리
- 행동 묶음(이동 → 기술)을 우선도 → 스피드 순으로 실행. 교체는 우선도 6으로 처리
- 기술마다 별도 범위: 지점형 3×3/십자/단일, 방향형 정면 3칸/직선/부채꼴. 지정 가능 거리와 실제 피해 범위를 분리
- 두 플레이어가 턴 시작 상태에서 명령을 선택. AI도 플레이어의 확정 명령을 읽지 않고 선택
- 기술은 지정 지점 또는 선택 방향의 범위를 공격. 상대 이동 시 범위 밖으로 피할 수 있음
- AI는 도달 가능한 위치와 기술의 예상 피해를 평가하되 상대 이동은 확실히 알지 못함
- 상대 점유 칸은 통과/도착 불가. 이동 실행 시 경로가 막히면 재탐색, 도달 불가면 제자리
- 자발적 교체는 기존 칸에서 이루어지고 한 턴을 소모
- 기절 후에는 다음 생존 포켓몬을 자동 출전시킴. 턴 사이에 시작 진영에서 등장
- 명중률/급소/피해 난수/상태이상/날씨/특성/도구/상태 변화는 초안에서 제외
- 기술 구성은 프로토타입용. 세대별 습득 합법성은 아직 보장하지 않음

## 확장 순서

1. 세대 기준 확정과 기술 구성 검증, 기절 후 출전 포켓몬 직접 선택
2. 광역/관통/추적 기술, 기술별 애니메이션, 후공 조건 효과
3. 상태이상·특성·방어·강제 교체 등 효과 처리기
4. 대사·맵 탐험·보상·포획으로 스토리 확장
5. PVP용 결정적 상태 머신, 서버 명령 잠금/공개, 재접속 및 동기화

현재 PvP 서버나 계정은 만들지 않았습니다. 브라우저 로컬 저장만 사용합니다.

## 화면 정리 변경

챕터 목록·도감 메뉴·설명·배틀 기록을 메인 화면에서 제거했습니다. 전장, 이름과 HP, 팀 교체, 4개 기술과 행동 버튼만 표시합니다. 전체 포켓몬 데이터는 그대로 보관합니다. 이동은 대각선을 포함한 인접 8칸 또는 제자리이며 AI에도 같은 규칙을 적용합니다.

## 기술 범위와 효과 확장

`moves.js`에서 현재 사용 중인 28개 기술의 범위와 효과 키를 각각 관리합니다. `engine.js`의 `attackTiles()`를 화면 미리보기·AI·명중 판정·애니메이션이 함께 사용합니다. 지점형은 체비쇼프 거리로 조준하고, 방향형은 상하좌우 방향을 선택합니다. 맵 밖과 시전자 자신의 칸은 피해 범위에서 제외합니다. 넓은 범위에 포함되어도 대상 하나에 한 번만 피해를 줍니다.

10만볼트 3×3, 전기쇼크 십자, 몸통박치기 정면 3칸, 물대포 직선, 파도타기 폭 3칸 직선, 화염방사/잎날가르기 부채꼴 등은 이 타일 게임의 커스텀 규칙입니다.

선택 상태는 `idle → move → skill → target → 실행 → idle`입니다. 처음에는 본인 포켓몬만 클릭할 수 있습니다. 같은 칸을 다시 선택하면 제자리 공격을 준비합니다. 이동은 동시 명령의 일부로 예약되며 화면에 예정 위치를 보여줍니다. 턴 확정 시 기술 우선도와 스피드로 정한 순서에 따라 각 포켓몬의 이동과 기술을 연속 처리합니다.

초기의 코드 기반 도형 이펙트는 제거했습니다. 현재 `sprite-effects.js`는 `pret/pokeemerald`에서 받은 기존 에메랄드 그래픽 55종/210프레임을 사용합니다. 원본 색과 픽셀을 유지하고 팔레트 0번의 투명 처리 및 가로 프레임 패킹만 수행했습니다. 기술별 배치와 타이밍은 타일 전장에 맞춘 구성이며 원작 전체 연출의 완전한 재현은 아닙니다.

## 순차 행동 연출

각 포켓몬이 520ms 동안 그림자와 함께 이동 → 160ms 준비 → 기술별 850~1650ms 효과 → 550ms 간격 순으로 행동합니다. 먼저 행동한 포켓몬의 기술과 피해 적용이 끝난 뒤 상대 행동을 시작합니다. 선공기로 행동 묶음 전체가 앞서며, 먼저 쓰러진 포켓몬은 이동/공격하지 못합니다. 제자리에서는 이동 연출만 생략합니다.

## 사거리, 타격 범위와 중심 급소

- 청록: 기술의 중심점/방향을 지정할 수 있는 사거리
- 주황: 해당 조준 위치에서 실제 피해를 주는 모든 칸
- 분홍 빗금: 마우스로 가리키거나 클릭하여 확정한 중심 한 칸. 실제 타격 범위 안에 있는 중심 칸만 급소로 취급
- 명중 시 상대의 실행 시점 위치가 급소 칸과 일치하면 확정 급소. 주변 타격 칸은 일반 피해
- 급소는 피해 공식에 1.5배 보정을 곱함. 물리 공격은 자신의 공격 하락/상대 방어 상승, 특수 공격은 자신의 특수공격 하락/상대 특수방어 상승을 0랭크로 취급. 자신의 상승/상대의 하락은 유지
- statStages는 -6~+6 랭크, 배율은 양수 (2+n)/2, 음수 2/(2-n). 원본 능력치/랭크 값 자체를 변경하지 않고 피해 계산에서만 무시
- 타입 무효는 급소여도 피해 0. AI도 동일한 급소 위치·계산 규칙을 사용
- 아직 랭크 변화 기술의 효과 처리는 구현하지 않았으며 현재 선출 포켓몬은 0랭크로 시작. 랭크 무시 계산은 물리·특수/불리·유리 변화 조합 테스트로 검증

참고: https://github.com/Zarel/Pokemon-Showdown-Dex/blob/master/articles/criticalhit.md

원작의 확률 급소와 달리, 이 게임에서는 중심 타일 명중을 조건으로 사용합니다.

## 다운로드한 이펙트 연결 검증

55개 시트의 PNG 크기와 메타데이터 일치, 28개 기술의 이미지 렌더링, 프레임 인덱스와 유효 좌표를 테스트했습니다. 기존 전투 계산/급소/순차 행동 테스트도 유지합니다. 이펙트 이미지는 로컬에서 미리 로드하며 동시 요청 수를 4개로 제한하고 일시적 실패는 최대 2회 재시도합니다.
