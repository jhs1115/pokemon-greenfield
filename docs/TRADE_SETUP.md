# 교환 연결

화면은 GitHub Pages에서, 방 생성·입장·실제 교환은 Supabase에서 실행합니다. 아래 두 단계를 해야 공개 사이트에서 교환할 수 있습니다.

## 서버 연결

1. 기존 계정 저장용 `supabase/schema.sql`을 실행한 Supabase 프로젝트에서 SQL Editor → New query를 엽니다.
2. `supabase/trade.sql` 전체를 붙여 넣고 Run 합니다. 기존 포켓몬·저장은 유지됩니다. 재실행할 수 있습니다.
3. GitHub Desktop → Repository → Open in Terminal로 저장소 폴더를 열고 실행합니다.

```powershell
npx --yes supabase login
npx --yes supabase functions deploy trade --remote=cncoztfeuzruykxiykfj --use-api --no-verify-jwt
```

로그인과 토큰 입력은 본인 컴퓨터에서 진행합니다. 비밀번호나 서비스 키를 채팅에 보낼 필요가 없습니다. 최신 CLI의 `--remote`를 사용하며 구버전은 `--project-ref cncoztfeuzruykxiykfj`로 대체할 수 있습니다. 함수는 내부에서 `auth.getUser()`로 로그인 토큰을 검사하고 서버 전용 RPC를 호출합니다. 테이블을 공개하거나 브라우저에 서비스 키를 넣지 마세요.

4. GitHub Desktop에서 변경을 Commit → Push origin 합니다. Pages 배포 후 새로고침합니다. PVP도 배포할 경우 [PVP 안내](PVP_SETUP.md)의 SQL과 별도 `pvp` 함수가 필요합니다.

## 사용

- 각자 로그인한 계정의 저장 파일을 엽니다.
- 한쪽이 메인 → 교환 → 교환 호스트를 눌러 8자리 코드를 알려줍니다.
- 다른 쪽은 교환 코드 입력 → 교환 입장으로 같은 방에 들어갑니다.
- 각자 보유 포켓몬 한 마리를 눌러 교환창에 올립니다. 양쪽의 종·레벨·장착 기술을 확인한 후 교환 확정을 누릅니다.
- 양쪽 모두 확정해야 실제로 교환됩니다. 포켓몬 변경/확정 취소는 양쪽 승인을 해제합니다. 화면에 표시된 제안 이후 상대가 변경했다면 이전 제안에 대한 확정은 거절됩니다.
- 교환 후 확인을 누르면 메인으로 돌아갑니다. 포켓몬 관리에 받은 포켓몬이 표시됩니다.

레벨·경험치·기술·배운 기술 기록·특성 설정은 받는 사람에게 전달합니다. 지닌 도구는 보내는 사람의 가방으로 돌려놓습니다. 스토리 선출에 있던 포켓몬은 받은 포켓몬으로 대체하고 PVP 등록 목록은 비웁니다. 현재 종별 한 마리 보관 구조이므로 이미 소유한 종은 받을 수 없습니다. 통신진화는 자동 적용하지 않습니다.

교환방은 30분 동안 유효하며 한 계정은 한 방에 참여합니다. 나가기 시 미완료 교환방이 닫히며 포켓몬은 이동하지 않습니다. 브라우저를 닫았을 때는 방이 만료될 때까지 남아 있을 수 있고 같은 계정으로 다시 호스트를 누르면 기존 방으로 복귀합니다.

## 검증과 범위

`npm test`에 실제 PostgreSQL 호환 엔진에서 방 코드·참여자 격리·소유 검사·양쪽 승인·제안 변경·두 저장의 원자적 교환·저장 버전 증가·도구 반환·중복 방지 검사가 포함됩니다. `GameAccount.refreshSlot()`이 서버에서 변경된 저장과 버전을 다시 읽으므로 다음 자동 저장이 이전 포켓몬 목록으로 덮어쓰지 않습니다. 저장 충돌이 발생한 상태에서는 교환을 시작하지 않습니다.

`tests/trade-preview.html`과 `tests/serve-trade.cjs`는 가짜 두 계정과 메모리 DB를 사용하는 로컬 검증용입니다. 실제 계정 저장을 사용하지 않습니다.

현재 소유 목록은 계정의 클라우드 저장 기준입니다. 스토리 획득 이력을 서버에서 검증하는 별도 부정행위 방지 장부는 아직 없습니다. 교환 완료는 두 저장 파일과 방 상태를 같은 DB 트랜잭션으로 갱신하며 재요청으로 교환이 반복되지 않습니다.
